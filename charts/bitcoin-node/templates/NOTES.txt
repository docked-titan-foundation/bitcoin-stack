Two things that will cost you days if you learn them the hard way:

  1. NEVER `kubectl delete pod --force` this node. SIGKILL during a chainstate
     flush corrupts the datadir, and the repair is a multi-day reindex. A plain
     `kubectl delete pod` and up to {{ .Values.terminationGracePeriodSeconds }}s of patience is the correct move.

  2. `storage.size` and `storage.storageClass` CANNOT be changed by editing
     values and upgrading. They live in the StatefulSet's volumeClaimTemplates,
     which Kubernetes forbids updating — the API server will reject the whole
     StatefulSet apply, and it keeps rejecting it, so every later change to this
     release silently stops landing too. To grow the volume:

       kubectl patch pvc data-{{ include "bitcoin-node.name" . }}-0 -n {{ .Release.Namespace }} \
         -p '{"spec":{"resources":{"requests":{"storage":"<new size>"}}}}'
       # then update storage.size to match, and:
       kubectl delete statefulset {{ include "bitcoin-node.name" . }} -n {{ .Release.Namespace }} --cascade=orphan
       helm upgrade ...

     --cascade=orphan leaves the running pod and the PVC alone. The node never
     stops.
