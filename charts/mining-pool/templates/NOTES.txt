{{- if .Values.bitcoin.waitForSync.enabled }}

  The pool waits for the node before it starts. Until the node finishes initial
  block download it has no valid work to serve, so the pod sits in Init as
  "wait-for-node-sync" (watch: kubectl get pod -n {{ .Release.Namespace }} -l app.kubernetes.io/name={{ include "mining-pool.name" . }}).
  On a fresh mainnet node that is days, and is expected. Set
  bitcoin.waitForSync.enabled=false to start the pool immediately instead.

A pool is only as fresh as its block notifications. This chart wires ZMQ
({{ include "mining-pool.zmqHost" . }}) so the pool rebuilds the block template the
instant a new block lands. Without it, miners grind stale work for seconds after
every block — which is time spent mining a block that can no longer be won.
